## 1) نطاق العمل

بناء نظام استيراد جماعي للمخزون بواجهتين (Web للصيدلي + API للموبايل) يسمح
برفع ملف Excel/CSV، معاينته بلا أي كتابة، مراجعة كل سطر، ثم تنفيذ مقسّم.

**التدفق المُنفَّذ:** تنزيل القالب → رفع → تحقّق → تحليل → حل الأسماء →
كشف التكرار → Dry-run → معاينة → قرارات المستخدم → Commit مقسّم → تقرير.

## 2) ما فُحص فعلياً قبل الكتابة (PHASE 0)

| ما فُحص | النتيجة المؤثرة في التصميم |
|---|---|
| `pharmacy_medicines` | فيه `unique(pharmacy_id, medicine_id)` ⇒ الـ upsert ممكن وآمن (idempotent) |
| `min_stock` | **مخزَّن ولا يُستخدم فعلياً** — `LowStockNotifier` يستخدم `LOW_STOCK_THRESHOLD` الثابت |
| `MedicineResolver::lookupMapping()` | يمسح ملف 13MB **لكل استعلام** ⇒ 5000 صف = 5000 مسحة |
| `MedicineResolver` | فيه كاش لكل استعلام، لكنه لا يحمي من 5000 استعلام مختلف |
| `LowStockNotifier` | يُطلق FCM **لكل نداء** ⇒ استدعاؤه صفاً صفاً = آلاف الإشعارات |
| `WithHeadingRow` (Maatwebsite) | `HeadingRowFormatter` **حالة عامة قابلة للتغيير** ⇒ خطر تسرّب بين الطلبات |
| قرص `local` في Laravel 13 | جذره `storage/app/private` ⇒ بناء المسار يدوياً يُنتج مساراً خاطئاً |
| `QUEUE_CONNECTION` | `sync` ولا يوجد أي Job/Event ⇒ لا بنية طوابير تُكسَر |
| `LogsExport::safeCell` | سابقة حماية CSV Injection في المشروع ⇒ نتبعها حرفياً |
| `med_medicines_version` | كاش قائمة الأدوية العامة يُبطَل عند إنشاء دواء |
| `bootstrap/app.php` | `writes` = 20/دقيقة بمفتاح `user_id` أو IP |
| `Dockerfile` | يبني الأصول (`npm run build`) وقت النشر ⇒ إضافة ملف CSS آمنة |
| `EnsureRole` / `EnsureProfileComplete` | الصيدلي غير المكتمل يُحوَّل؛ غير الصيدلي يُحوَّل لصفحة الدخول |

**عطل حقيقي اكتُشف أثناء الفحص:** قارئ CSV يخمّن فاصل الأعمدة من أول سطر.
ملف يبدأ بسطر عنوان بلا فواصل (مثل «تقرير مخزون») يجعله يختار فاصلاً خاطئاً،
فينهار التحليل برسالة «لم نتعرّف على صف العناوين» وهي **مضلِّلة**. أُصلح بكشف
الفاصل من محتوى الملف (تفصيل في §17).

## 5) نماذج البيانات والهجرات

**`inventory_imports`** (جديدة)
`id, uuid(unique), pharmacy_id(FK cascade), user_id(FK cascade), original_filename,
file_hash(64), file_path, status(20), total_rows, matched_rows, review_rows,
unmatched_rows, duplicate_rows, error_rows, committed_rows, created_medicines,
rows_payload(longText), commit_summary(longText), committed_at, expires_at, timestamps`
الفهارس: `(pharmacy_id, status)` · `expires_at`.

**`pharmacy_medicine_aliases`** (جديدة)
`id, pharmacy_id(FK), medicine_id(FK), alias(191), timestamps`
`unique(pharmacy_id, alias)` باسم `unique_pharmacy_alias` + فهرس `(pharmacy_id, medicine_id)`.

**لماذا لا Cache لحالة الجلسة:** القرارات نتائج عمل بشري يجب أن تنجو من انتهاء
الجلسة وإعادة التشغيل وإعادة النشر. `Cache` يفقدها بصمت.

**لماذا `uuid` في الروابط:** منع تعداد جلسات الآخرين؛ ويُفلتر إضافةً بذلك
بـ `pharmacy_id` و `user_id`.

## 6) حل الأسماء والمطابقة الحتمية

سلّم واحد، أول قاعدة تنجح تفوز — **لا رقم ثقة مُختلق**:

| # | القاعدة | الحالة |
|---|---|---|
| 1 | مطابقة تامة بالاسم الإنجليزي في الكتالوج المحلي | `EXACT_EN` |
| 2 | مطابقة تامة بالاسم العربي بعد التطبيع | `EXACT_AR_NORMALIZED` |
| 3 | مرادف مؤكَّد سابقاً لهذه الصيدلية | `ALIAS_MATCH` |
| 4 | مطابقة تامة في كتالوج وزارة الصحة | `MOH_MATCH` |
| 5 | مطابقة تقريبية بمرشّح واحد | `FUZZY_MATCH` |
| 5ب | مطابقة تقريبية بأكثر من مرشّح | `REVIEW_REQUIRED` |
| 6 | لا شيء | `UNMATCHED` |
| — | صف غير صالح بنيوياً | `INVALID_ROW` |
| — | أكثر من صف لنفس الدواء | `DUPLICATE` |

**الترتيب مقصود:** المطابقة التامة تتقدّم على المرادف لأنها إشارة موضوعية
لا تعتمد على قرار سابق — نتجنّب تجاوزاً مفاجئاً لدواء موجود فعلاً.

**الحالات 1–3** قابلة للتنفيذ بلا سؤال. **الحالات 4–6 والتكرار** تتطلّب قراراً صريحاً.

### الأداء: من N مسحة إلى مسحة واحدة
`MedicineResolver::lookupMappingBatch()` جديدة — **مسحة واحدة** للملف لكل
الاستعلامات، مع بوّابة `str_contains` رخيصة مثبَت أنها **superset** للمطابق
الأصلي (لا نتائج مفقودة). المنطق نفسه استُخرج إلى `recordMatchesNeedle()`
**حرفياً** لتُعاد استخدامه بلا تكرار — تثبته اختبارات `MedicineResolveTest`
القائمة (28 اختباراً) التي مرّت كما هي.

**حدّان للحماية:** `fuzzy_max_queries` (2000) — ملف كله غير مطابق لا يستحق
مسحاً مكلفاً؛ و`allBucketsFull()` للتوقّف المبكر.

## 7) منع تلويث الكتالوج (الأولوية القصوى)

- **لا إنشاء تلقائي إطلاقاً.** الإنشاء يحتاج `DECISION_CREATE` صريحاً محفوظاً
  على الخادم.
- **المطابقة التقريبية لا تُنشئ شيئاً** — تُنتج اقتراحاً فقط.
- **`moh_id` يجب أن يكون من اقتراحات الصف نفسه** — وإلا رُفض الطلب (422).
  هذا يمنع الواجهة من توجيه الإنشاء لأي عنصر في الكتالوج.
- **`medicine_id` يُعاد التحقق منه** مقابل فهرس حديث من DB — لا نثق بالمعرّف القادم.
- **إعادة التحقق قبل الإنشاء:** `resolveByName(..., lookupMoh: false)` مرة أخرى،
  فقد يكون الدواء أُنشئ بين المعاينة والتنفيذ ⇒ **لا دواء مكرّر**.
- **تأكيد صريح في الواجهة:** عند وجود أدوية جديدة، نافذة تأكيد تذكر العدد بالاسم
  قبل الإرسال.
- **إبطال الكاش:** `MedicineCatalogCache::bump()` يُنادى **فقط** عند
  `created_medicines > 0` — وإلا فالكاش سليم.

## 8) كشف التكرار وقرارات الدمج

- مفتاح المجموعة: `m:{medicine_id}` أو `moh:{moh_id}` أو `in:{اسم مطبّع}`.
- **لا جمع كميات ولا دمج صامت** — الكمية قيمة مطلقة، فجمع صفين لا معنى له.
- **قرار صريح لكل مجموعة:** `keep_last` / `keep_first` / `skip_all`.
- الفائز يُحدَّد حتمياً: `keep_first` ⇒ أصغر رقم سطر، `keep_last` ⇒ أكبره.
- **الخاسر لا يحتاج قراراً فردياً** — قراره محكوم بقرار المجموعة (مثبَّت باختبار).
- المجموعة بلا قرار **تمنع التنفيذ** (لا فائز ⇒ لا كتابة).

**لماذا لا "آخر كتابة تفوز" تلقائياً:** في MySQL بلا `ORDER BY` الترتيب
غير معرَّف، فيصير الناتج عشوائياً — وهو أسوأ من مطالبة المستخدم بقرار.

## 9) Idempotency والـ Commit الذرّي

**الحجز الذرّي** — جملة `UPDATE` واحدة تشمل فحص الحالة وعدم الانتهاء:

```sql
UPDATE inventory_imports
   SET status = 'committed', committed_at = NOW(), updated_at = NOW()
 WHERE id = ? AND pharmacy_id = ?
   AND status IN ('previewed','ready')
   AND (expires_at IS NULL OR expires_at > NOW())
```

`affected_rows == 0` ⇒ رفض «نُفِّذت مسبقاً». **لا فجوة بين الفحص والتنفيذ**،
فالتنفيذ المزدوج مستحيل حتى مع طلبين متزامنين.

**الدفعات:** كل دفعة (`chunk_size` = 500، قابل للضبط) داخل `DB::transaction`
مستقل — لا معاملة واحدة عملاقة تُقفل الجداول وتستهلك الذاكرة.

**عند الفشل:** تُعاد الجلسة إلى `ready`، ويُسجَّل السبب داخلياً، وتُعرض للمستخدم
رسالة عامة بلا تفاصيل داخلية.

**Upsert مقسوم:** الصفوف التي فيها `min_stock` تُكتب معه، والتي لا `min_stock`
فيها **لا تلمسه إطلاقاً** (تفصيل في §14).

## 10) الأداء — لا N+1

| العملية | الاستعلامات |
|---|---|
| بناء الفهرس | **3** ثابتة: `medicines` + `moh_medicines` + `aliases` |
| حل 5000 صف | **0** (كل شيء في الذاكرة) |
| مطابقة تقريبية لملف كامل | **1** مسحة واحدة لملف الـ mapping |
| كتابة 5000 صف | دفعات 500 ⇒ ~10 `upsert` |

`medicines` يُحمَّل كاملاً بمقاطع `chunkById(2000)` (جدول محدود الحجم بطبيعته)،
وهذا يزيل أيضاً **اختلاف حساسية حالة الأحرف** بين MySQL (غير حساس) وSQLite
(حساس) — فتصبح النتيجة واحدة في الإنتاج والاختبار. ويلغي الاعتماد على فهرس
غير موجود على `trade_name_ar`.

الترتيب تصاعدي بالـ `id` مع «أول فوز» ⇒ نفس دلالة `first()` الأصلية.

## 11) الأمان — كل شيء يُعاد التحقق منه على الخادم

| المخاطرة | الإجراء |
|---|---|
| ثقة بـ `medicine_id` من الواجهة | يُتحقّق وجوده في فهرس حديث من DB |
| ثقة بـ `moh_id` من الواجهة | يجب أن يكون من اقتراحات الصف نفسه |
| ثقة بـ `import_id` | يُجلب بـ `uuid` + `pharmacy_id` + `user_id` |
| اسم ملف خبيث / path traversal | اسم مولَّد من الخادم (`uuid.ext`)؛ الاسم الأصلي للعرض فقط بعد إزالة الفواصل |
| امتداد مزيّف | قائمة بيضاء للامتدادات **و** أنواع MIME |
| ملف ضخم | `max_file_kb` (5MB) + `max_rows` (5000) |
| صيغة تُنفَّذ في Excel (CSV Injection) | `safeCell()` مطابق لـ `LogsExport` — `= + - @` تُسبق بـ `'` |
| تفاصيل داخلية في رسائل الخطأ | الفشل يُسجَّل داخلياً، والمستخدم يرى رسالة عامة |
| انتهاء الجلسة | `expires_at` يُفحص في كل عملية **وداخل** جملة الحجز |

**كل قرار يُعاد التحقق منه في `applyDecisions()`** — لا يُقبل شيء كما أرسلته الواجهة.

## 12) الصلاحيات ودورة حياة الجلسة

**دورة الحياة:**
`uploaded → previewed → ready → committed`، ومن `previewed/ready` ⇒ `expired` أو `failed`.

- **الصلاحيات:** `auth` + `role:pharmacy` + `profile.complete`.
- **العزل:** الصيدلية تُستنتج من المستخدم المسجَّل حصراً؛ جلسة صيدلية أخرى ⇒ **404**
  (مثبَّت باختبار ويب واختبار API).
- **الانتهاء:** `session_ttl_hours` (24) افتراضياً، والفحص مزدوج (خدمة + جملة الحجز).
- **لا تنفيذ مزدوج:** الحجز الذرّي (§9).
- **حذف الملف المؤقت** بعد النجاح أو الإلغاء، بلا إفشال العملية لو فشل الحذف.

## 13) حد المعدل

**Limiter جديد `inventory-import`** — منفصل تماماً عن `writes`، ولم يُرفع `writes`.

- **المفتاح = `user_id + pharmacy_id`** (وليس IP): خلف موازن Render يشترك كثير من
  المستخدمين في نفس IP، فمفتاح IP يصبح دلو مشتركاً يحجب أبرياء.
- **السقف:** `rate_limit_per_hour` (10/ساعة) — يرفع السقف للاستيراد دون فتح
  نقاط الكتابة الأخرى للإساءة.
- غير مسجَّل الدخول ⇒ `5/دقيقة` بمفتاح IP.
- **مثبَّت باختبارين:** مستخدم ثانٍ من نفس الـ IP لا يتأثر؛ استهلاك حد الاستيراد
  كاملاً لا يمسّ `writes`.

## 14) `min_stock` — لا كسر صامت

**الواقع المُكتشف:** `min_stock` مخزَّن ولا يُغيِّر حد التنبيه فعلياً —
`LowStockNotifier` يستخدم `PharmacyMedicine::LOW_STOCK_THRESHOLD` الثابت.

**ما نُفِّذ (الخيار الآمن):** يُحفظ `min_stock` كما هو، **ولا ندّعي** أنه يغيّر
التنبيهات. والأهم: الـ upsert **مقسوم** — الصفوف بلا `min_stock` تُكتب في قائمة
منفصلة **لا تتضمّن العمود**، فلا يمحو رفع ملف بلا هذا العمود قيماً موجودة.

**مثبَّت باختبارين:** الغائب يُبقي `7`، والحاضر يحدّثها إلى `4`.

---

## 15) الإشعارات (FCM)

- **لا `LowStockNotifier` لكل صف** — كان سيُنتج آلاف الإشعارات ودفعات FCM.
- **إشعار واحد مجمَّع** بعد نجاح التنفيذ: «تم استيراد مخزونك: N صنف محدَّث،
  وM صنف تحت حد النقص».
- **خارج المعاملة** تماماً.
- **فشل الإشعار لا يُفشل الاستيراد** — `try/catch` يلفّ الإنشاء والإرسال معاً،
  ويُسجَّل تحذير. مثبَّت باختبار يرمي فيه مزوّد الإشعارات استثناءً: الاستيراد
  ينجح والبيانات تُكتب.

## 16) القالب وتقرير الأخطاء

**`InventoryTemplateExport`** — وضعان:
- `empty`: صف عناوين فقط.
- `current`: المخزون الحالي بنفس ترتيب الأعمدة (استعلام واحد مع eager load).

**قرار مقصود:** لا صف مثال داخل الملف — صف مثال يُنسى فيُستورد فعلاً، ونداء
الأخطاء أغلى من ربح توضيحي. الشرح معروض في الواجهة بدلاً منه.

**`InventoryErrorsExport`** — نفس بنية القالب (كي يعدّل الصيدلي ملفه الأصلي
ويعيد رفعه) + أعمدة تشخيص: الحالة، الأخطاء، التحذيرات، الاقتراحات.
**حماية CSV Injection** مطبَّقة على كل خلية نصية — مثبَّتة باختبار يتحقّق أن
`=cmd|calc!A1` تُصدَّر `'=cmd|calc!A1`.

## 17) الواجهة (Web) والـ API

### الويب — 3 شاشات
| الشاشة | المحتوى |
|---|---|
| `import/index` | 4 خطوات + تنزيل القالب + دليل الأعمدة + منطقة رفع بالسحب + آخر الجلسات |
| `import/review` | ملخّص 6 عدّادات + بطاقات الدمج + فلترة + جدول الأسطر بمحرّر قرار + شريط تأكيد |
| `import/result` | نتيجة التنفيذ (أسطر محدَّثة/متجاوَزة/أدوية جديدة/مرادفات/نقص) أو رسالة الانتهاء |

**قرارات تصميم الواجهة:**
- **الحالة نص دائماً مع الشارة** — اللون تأكيد إضافي لا القناة الوحيدة للمعنى.
- **RTL بخصائص منطقية** (`inline-start/end`) بلا قواعد مكرّرة.
- **رفع مزدوج ممنوع** — الزر يُعطَّل بعد أول إرسال صالح.
- **قرارات افتراضية مشتقّة من قدرات الصف** (لا من حالة العرض) — لأن صفوف
  التكرار تُعاد كتابة حالتها إلى `DUPLICATE` وتفقد تصنيفها الأصلي.
- **بحث الكتالوج** يعيد استخدام نقطة `pharmacy.medicines.search` القائمة —
  **لا نقطة API جديدة ولا تغيير عقد**.
- **التنفيذ يمر بحفظ القرارات أولاً**: الزر يحفظ (AJAX) ثم يُرسل نموذج التنفيذ؛
  إن فشل الحفظ لا يُنفَّذ شيء.

### الـ API — مسار الموبايل
`GET/POST /api/pharmacy/inventory/import[...]` — **نفس محرّك الويب**، لا منطق
مكرّر ولا اختلاف قواعد. كل النقاط **إضافية بحتة** — لم يُعدَّل أي عقد قائم
(مثبَّت باختبار يتحقّق من شكل `GET /api/pharmacy/inventory` القديم).

### إصلاح قارئ CSV (عطل حقيقي)
`detectDelimiter()` يفحص أول 20 سطراً على البايتات الخام (الفواصل ASCII ⇒ لا
يتأثر بترميز UTF-8 أو Windows-1256) ويختار الفاصل الأكثر **اتساقاً** عبر الأسطر،
ثم يُمرَّر صراحةً للقارئ. المسافة ليست مرشّحاً — واعتبارها كذلك هو تحديداً ما
كان يُفسد ملفات فيها سطر عنوان. الإعداد يُعاد لحالته بعد القراءة.
مثبَّت بأربعة اختبارات (فاصلة منقوطة، سطر عنوان، فاصلة داخل قيمة، والافتراضي).

## 19) القيود المعروفة والخطوات التالية

**قيود مقصودة (مُعلَنة، لا صامتة):**

1. **`min_stock` لا يغيّر حد التنبيه فعلياً** — يُحفظ فقط. تغيير السلوك يحتاج
   تعديل `LowStockNotifier` لقراءته، وهو **تغيير منفصل** يستحق قراراً مستقلاً.
2. **عمود `barcode` معروف ويُهمل** — لا عمود له في الكتالوج ولا جدول باركود.
   مقبول ومُتجاهَل بتحذير حتى تُبنى ميزة الباركود.
3. **المطابقة التقريبية تعمل على الاسم الإنجليزي المُدخل** — لا على الاسم العربي
   وحده. صف بلا اسم إنجليزي ولا مطابقة تامة يبقى `UNMATCHED`.
4. **لا رفع خلفي (Background)** — التنفيذ داخل الطلب. عند 5000 صف مع دفعات 500
   هذا مقبول ضمن حدود Render، لكن الملفات الأكبر تحتاج طابوراً (مؤجَّل بوعي).
5. **`medicines` يُحمَّل كاملاً في الذاكرة** — مقبول لكتالوج بحجمه الحالي؛ لو
   نما إلى مئات الآلاف يحتاج الفهرس استعلامات `whereIn` مقيَّدة.

**قبل النشر:**
- تشغيل الهجرتين: `php artisan migrate`.
- `npm run build` (Dockerfile يفعله تلقائياً) — `pharmacy_import.css` جديد.
- ضبط متغيرات البيئة عند الحاجة: `INVENTORY_IMPORT_MAX_ROWS`,
  `INVENTORY_IMPORT_CHUNK_SIZE`, `INVENTORY_IMPORT_RATE_LIMIT_PER_HOUR`.

**لم يُنفَّذ (بانتظار قرار):** رفع خلفي بطابور · دعم الباركود · تعديل
`LowStockNotifier` ليقرأ `min_stock` · تحرير الجلسات المنتهية بمهمة مجدولة.
