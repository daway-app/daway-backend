# DAWAK — جدولة إعادة محاولة FCM: الخيارات والتوصية

**الهدف:** تشغيل `php artisan fcm:retry-failed --limit=200` دوريًا بأمان على Render Free.

---

## الخيارات

### A. Render Cron Job — **مدفوع بحد أدنى $1/شهر**

| | |
|---|---|
| التكلفة | **حد أدنى $1/شهر** لكل خدمة، تُحسب بالثانية حسب زمن التشغيل |
| الخطة المجانية | **لا تشملها** |
| الموثوقية | عالية — Render يضمن **ألا يعمل نسختان معًا** |
| الملفات السرية | **لكل خدمة نسختها**؛ المشاركة عبر Environment Group |
| الإعداد | `schedule: "*/15 * * * *"` · `dockerCommand: php artisan fcm:retry-failed --limit=200` |

**العيب الوحيد:** دولار شهري.

---

### B. جدولة خارجية (GitHub Actions / cron خارجي)

| | |
|---|---|
| التكلفة | مجاني |
| العيب الحاسم | يتطلب وضع **بيانات Aiven ومفتاح Firebase** في أسرار GitHub ⇒ توسيع سطح الهجوم |
| بديل مرفوض | Endpoint عام يستدعي الأمر — ممنوع صراحةً |

**لا أنصح به.** نقل أسرار الإنتاج إلى طرف ثالث مقابل توفير دولار ليس مقايضة جيدة.

---

### C. جدولة داخل خدمة الويب (`terminating` / `schedule:run`)

| | |
|---|---|
| التكلفة | صفر |
| العيب | **غير آمن مع `php artisan serve`** |

**الدليل من المستودع:** `Dockerfile:93` يشغّل `php artisan serve` — خادم **أحادي العملية**.
أي عمل في `terminating` ينفّذ **قبل** أن يقبل الخادم الطلب التالي، فيضيف زمنه إلى زمن استجابة الطلب التالي مباشرة. هذا يناقض شرطك بعدم الاعتماد قبل إثبات عدم التأثير.

كما أن الخدمة المجانية تنام بعد خمول ⇒ لا جدولة منتظمة أصلًا.

**مرفوض حاليًا.**

---

## التوصية

### للاستخدام الفوري (مجاني)
**تشغيل يدوي عند الحاجة:**
```bash
php artisan fcm:retry-failed --limit=200
```
مع `fcm:stats` للتحقق. مناسب الآن لأن حجم الإشعارات اليومي صغير (90 إشعارًا إجمالًا حتى اليوم).

### عند نمو الاستخدام (دولار واحد)
**Render Cron Job** كل 15 دقيقة — الخيار الوحيد الموثوق والمنضبط.

---

## لماذا القفل موجود أصلًا

Render يضمن تشغيل نسخة واحدة من نفس الـcron. القفل المشترك (`Cache::store('database')`) يبقى طبقة ثانية تحمي من:
- تشغيل يدوي متزامن مع cron.
- مستقبلًا: أكثر من خدمة تعالج نفس الصفوف.

مُثبت عمليًا: عملية تحمل القفل ⇒ الأمر يطبع `retry already running — skipped`.

## المراقبة

```bash
php artisan fcm:stats --hours=24
# sent=120 failed=4 skipped=9 pending=0
# failure_codes: UNAVAILABLE=3, UNREGISTERED=1
```

- **تجميعي فقط**: أعداد ورموز FCM. لا معرّفات ولا توكنات ولا أنواع إشعارات.
- رمز الخروج `1` عند وجود فشل أو معلّق ⇒ يصلح للتنبيه الآلي لاحقًا.
- `skipped` مرتفع يعني غياب أجهزة أو غياب الإعداد — يستحق النظر.

**مقترح لاحقًا (لا يُنفَّذ الآن):** إضافة `fcm: {failed: N, pending: M}` إلى `/healthz` — قيم تجميعية لا تكشف شيئًا.
