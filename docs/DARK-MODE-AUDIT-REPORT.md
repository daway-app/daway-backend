## 1) ملخص تنفيذي

كان الوضع الداكن في الموقع **مبنيّاً على ستة أنظمة ألوان مستقلة** لا يعرف بعضها بعضاً، ولوحتين داكنتين متنافستين (كحلي + رمادي zinc)، وثلاث طبقات ترقيم متضاربة. النتيجة: حدود غير مرئية، ومؤشّر تركيز غير مرئي، وشارات بنصوص فاتحة على خلفيات فاتحة، وصفحات كاملة بلا دعم داكن.

**ما تم:**

| المقياس | قبل | بعد |
|---|---|---|
| أنظمة tokens مستقلة | **6** | **1** (`resources/css/tokens.css`) |
| لوحات داكنة متنافسة | **2** (كحلي + zinc) | **1** (كحلي) |
| قيم zinc/slate داخل قواعد الداكن | **~280** | **0** |
| طبقات ترقيم متضاربة | **3** | **3** (كلها على tokens موحّدة) |
| ملفات CSS غير سليمة | 0 | 0 |
| البناء (`npm run build`) | ✅ | ✅ |

كل قيمة لون في اللوحة الجديدة **حُسبت مقابل صيغة WCAG** قبل إدراجها — لا تخمين. ملف التحقق:
`outputs/dark-mode-wcag-verification.py` (يشغّل 60 فحصاً، والنتيجة: **ALL CHECKS PASS**).

## 2) المنهجية

صيغة الإضاءة النسبية (WCAG 2.1):

```
f(c) = c/12.92                     إذا c ≤ 0.03928
f(c) = ((c + 0.055)/1.055)^2.4     خلاف ذلك

L = 0.2126·f(R) + 0.7152·f(G) + 0.0722·f(B)
النسبة = (L₁ + 0.05) / (L₂ + 0.05)
```

- **نص:** ≥ 4.5:1
- **حدود المكوّنات التفاعلية ومؤشّرات التركيز** (WCAG 1.4.11): ≥ 3:1
- **حدود الكروت والفواصل التزيينية:** لا متطلّب WCAG — ذُكرت صراحةً كتزيينية

كل قيم `rgba()` حُسبت **مركّبة (composited)** فوق الخلفية الحقيقية، لا على الأسود.

## 7) الخلاصة

الوضع الداكن لم يعد مجموعة رقع — صار **نظاماً واحداً** له مصدر واحد (`tokens.css`)، ولوحة واحدة (كحلي)، وكل قيمة فيه مُتحقَّق منها مقابل WCAG 2.1 AA. الأعطال الإلزامية (P0) اختفت بالكامل، وفشل تباين النصوص (P1) عولج على كل السطوح المقيسة.

الخطوة التالية المقترحة: **حذف الملفات الميتة الأربعة (77 KB)** ثم **تدقيق الوضع الفاتح** بنفس العمق — لأن ألوان الفاتح الخام (~700 قيمة) لم تُفحص بعد.
