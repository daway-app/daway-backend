# عقد الطلب والدفع والتوصيل لتطبيق Flutter

هذا المستند يصف العقد الفعلي في Laravel. لا تحسب الواجهة الأسعار أو تغيّر الحالات محليًا؛ تعرض ما يعيده الخادم.

## المال والعملة

- العملة المعتمدة هي الشيكل (`₪` / `ILS`). لا يوجد تحويل عملات.
- `total` هو مجموع أدوية الطلب بعد الخصم ولا يشمل التوصيل.
- `delivery_fee` رسم رحلة موحّد محفوظ لحظة الـcheckout، حتى عند تعدد الصيدليات.
- `grand_total = total + delivery_fee` وهو الرقم الملزم للدفع.
- لا يرسل Flutter سعرًا أو رسم توصيل موثوقًا عند الـcheckout؛ الخادم يحسبهما من الأسعار والعنوان وإعدادات التسعير.
- إذا كان التسعير معطّلًا أو الإحداثيات/الشريحة غير صالحة، يفشل الـcheckout بـ`422` وحقل `errors.delivery_fee` ولا ينشأ طلب.

## حالات الطلب الأب

| القيمة | النص المقترح للمريض |
|---|---|
| `pending` | بانتظار الدفع |
| `confirmed` | تم تأكيد الطلب |
| `preparing` | جاري تجهيز الطلب |
| `ready` | جاهز للاستلام أو التوصيل |
| `picked_up` | استلم المندوب الطلبات المطلوبة |
| `out_for_delivery` | خرج للتوصيل |
| `delivered` | تم الاستلام |
| `cancelled` | ملغي |

في الطلب متعدد الصيدليات يشتق الخادم حالة الأب من أبطأ `SubOrder` نشط. بعد أن يبدأ المندوب الاستلام تصبح حالة التوصيل بيده. لا تعلن الواجهة `delivered` قبل أن تعيد API حالة الأب `delivered`.

## حالات الدفع

| `payment_status` | المعنى | تصرف Flutter |
|---|---|---|
| `pending` | بانتظار الدفع | اعرض البنوك وخيار رفع الإيصال أو البلاغ إذا سمحت flags الخادم |
| `under_review` | إيصال قيد مراجعة الأدمن | لا تعده مدفوعًا |
| `problem_reported` | بلاغ دفع مفتوح | اعرض البلاغ؛ لا تعده مدفوعًا ولا تعرض نجاح الدفع |
| `rejected` | الإيصال مرفوض | اعرض السبب إن أعادته API واسمح بإيصال جديد عند `can_submit_receipt` |
| `paid` | اعتمد الأدمن الدفع | يمكن للخادم متابعة التجهيز والتوصيل |

المسار `POST /api/patient/orders/{order}/payment/problem` لا يتطلب إيصالًا أو `submission_id`. عند نجاحه يعيد `201` و`data.payment_status = "problem_reported"`. إذا ظهرت الشاشة بعده `pending`، فهذا يعني أن التطبيق لم يستلم نجاح المسار أو أعاد قراءة طلب مختلف/بيانات مخزنة؛ لا توجد قاعدة خادم تعيد البلاغ الناجح إلى `pending` قبل أن يحله الأدمن.

## التقييم

`POST /api/ratings` يقبل `pharmacy_id`, `stars_rating`, و`comment?` للمريض فقط. يستلزم أن يملك المريض طلبًا أبًا `delivered` وأن يكون طلب الصيدلية نفسها `delivered` ضمن طلب مكتمل. التقييم واحد لكل `(user_id, pharmacy_id)`.
